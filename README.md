# TagMaster · 打标高手

给动画片段自动打标签，也能把 Premiere 里的剪辑点批量切成片段。

- **打标**：每段抽 2 帧，让模型看图，输出 `景别 / 人数 / 朝向 / 主体 / 动作 / 场景 / 光线 / 情绪` 八个字段，另附 `风格 / 色调 / 字幕` 三个扩展字段（运镜只从文件名导入时填）
- **切片段**：读 PR 导出的 FCP XML，按里面的帧号把片段全部切出来
- **素材库模式**：打好的片段直接落进按作品分好的素材库文件夹，标签表 / 预览页收进 `_标签数据\`
- **导入已有片段**：老素材不用重跑模型，按文件名就能建标签表、进预览页（不改名、不复制）
- **只补标签**：对已有素材跑模型补全字段，同样不改名、不复制，标签原地写回
- **发送到 Premiere**：CEP 面板桥，预览页勾选或页面按钮一键把片段送进 PR 项目（见⑥）

一句话：**先切，再打标，然后按标签挑素材。**

## 一、运行要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| 显卡 | **NVIDIA，显存 8 GB 以上**（没有 N 卡无法运行，CPU 跑不动） |
| 磁盘 | 约 **12 GB**（运行环境 5.3 G + 模型 5.4 G） |
| 其它 | Python、ffmpeg **随完整程序包自带**（仓库不含，自备方法见第五节）；不用装 CUDA Toolkit（torch 自带运行时），但 **NVIDIA 显卡驱动必须装** |

## 二、仓库里有什么

仓库是**纯代码，8 个文件、约 80 KB**：

```
TagMaster.py                          主程序（界面 + 流程）
TagMaster.bat                         启动器
README.md                             本文件
使用说明.txt                            日常操作说明

A_coreUtils\aftertreatment\__init__.py
A_coreUtils\aftertreatment\shot_analyzer.py         MiniCPM 加载封装
```

**只有 `python\` 和 `models\` 需要自备** —— 两者合计 10.7 GB，
GitHub 放不下，也不该放（模型有自己的许可，视频素材更涉及版权）。

程序跑起来后还会在目录里生成 `设置.json`（记住上次的路径和勾选项），
属于本机状态，不进仓库，删掉就恢复默认。

## 四、每样东西具体放什么

### 1. `python\` —— Python 3.11 嵌入式环境（5.3 G）

**目录里应该看到：**

```
python\
├─ python.exe
├─ pythonw.exe
├─ python311._pth
└─ Lib\
   └─ site-packages\      ← 这里有 torch、transformers、cv2、PIL
```

**怎么弄到：**

推荐做法 —— **从一台已经能跑的机器上，把这个 `python` 文件夹整个复制过来**。

因为往嵌入式 Python 里装 CUDA 版 torch 很容易失败（权限、编译依赖、路径），
复制是最省事的。整个目录可以随意移动，它用的是相对路径。

自己装的话（不推荐，容易踩坑）：

```bat
python\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128
python\python.exe -m pip install transformers accelerate pillow opencv-python numpy pyarrow
```

**验证通过的环境：** Python 3.11.2 / torch 2.9.1+cu128 / transformers 5.7.0

---

### 2. `models\MiniCPM-V-4-6\` —— 打标模型（2.5 G）

**目录里应该看到：**

```
MiniCPM-V-4-6\
├─ config.json              ← 必需
├─ model.safetensors        ← 必需，2.5 G
├─ tokenizer.json
├─ tokenizer_config.json
├─ preprocessor_config.json
├─ chat_template.jinja
└─ generation_config.json
```

**从哪来：** HuggingFace 或 ModelScope 上的 MiniCPM-V 系列（面壁智能）。
搜 `MiniCPM-V`，找 4.6 这个版本，整仓下载后把文件夹改名成 `MiniCPM-V-4-6`。

也可以直接从能跑的机器复制这 2.5 G。

---

### 3. `models\aslakey_shot_scale\` —— 景别模型（1.2 G）

**目录里应该看到：**

```
aslakey_shot_scale\
├─ config.json              ← 必需
├─ model.safetensors        ← 必需，1.2 G
└─ preprocessor_config.json ← 原仓库可能没有，程序可一键生成
```

**从哪来：** HuggingFace 上的 `aslakey/shot-scale`（DinoV2 微调的景别分类器）。

**注意第三个文件：** 原模型仓库里通常**没有** `preprocessor_config.json`。
缺了它，景别这一列会静默失效（全部空着，但程序不报错）。
新版 transformers 里 DinoV2 的处理器映射到了 `BitImageProcessor`，
程序自检窗口里有一键生成按钮，会写入正确的配置。

---

### 4. `models\ffmpeg\` —— 抽帧与切片（319 M）

**目录里应该看到：**

```
ffmpeg\
└─ bin\
   ├─ ffmpeg.exe           ← 必需
   └─ ffprobe.exe          ← 必需
```

**从哪来：** Windows 版 ffmpeg 静态构建（gyan.dev 或 BtbN 的 release），
解压后把整个文件夹改名成 `ffmpeg` 放进 `models\`。

> 用新版 ffmpeg 时有个坑：`-vsync` 参数在 2026 年的构建里已被删除，
> 本项目已经改用 `-fps_mode`，不会踩到。

---

### 5. `A_coreUtils\aftertreatment\` —— 模型加载封装（20 K，自带）

**随程序发布，不需要另外准备。** 目录里是：

```
A_coreUtils\
├─ __init__.py
└─ aftertreatment\
   ├─ __init__.py
   ├─ shot_analyzer.py           ← 加载 MiniCPM-V 并推理
   └─ shot_type_classifier.py    ← 加载 DinoV2 并判景别
```

两个文件各做一件事：把模型加载进显存，暴露一个简单接口。合计约 300 行。

> 接口设计与 **TuanToolKit**（原作者）的同名模块保持一致，在此致谢。
> 本仓库里的是独立实现，不复用其源码。

## 五、缺东西会怎么样

**不会静默失败。** 程序启动时会自动检查，缺什么弹窗列出来：

```
环境检查
有 3 项缺失，补齐后才能正常使用

✕ MiniCPM-V-4-6（打标模型）
   D:\TagMaster\models\MiniCPM-V-4-6
   整个模型文件夹放到 models\MiniCPM-V-4-6\，约 2.5G

✕ 景别模型的处理器配置
```

（上面是示意，实际显示的是**你自己程序目录**下的路径。）

每项都给出**期望的完整路径**和一句话说明。补齐后点「重新检测」，
全部变成绿色勾就可以开始用了。

顶部右上角有「环境检查」按钮，随时可以再打开。

## 六、怎么用

### ① 切片段（PR 场景检测 → XML → 批量切）

1. PR 里对素材右键 → 场景编辑检测 → 勾「在每个检测到的剪切点应用剪辑」
2. 文件 → 导出 → **Final Cut Pro XML**
3. TagMaster 切到「② 切片段」页，选这个 XML
4. 源视频目录填原片现在所在的文件夹（原片挪过位置就靠这一项）
5. 点「开始切片段」

输出：`序列名_0001.mp4`、`序列名_0002.mp4`……顺序即时间线顺序。
418 段约 4 分钟（NVENC 硬编，失败自动退 CPU）。

### ② 打标

1. 切到「① 打标」页，素材目录选刚才的输出目录
2. 点「开始打标」

输出到 `素材目录_打标\`：

```
clips\          改名后的副本（原片不动）
thumbs\         缩略图
tags.csv        标签表，Excel 可开
preview.html    按标签筛选的预览页
```

文件名形如：

```
中景_单人_侧脸_少女 金发_站立_森林_白天_平静_0183.mp4
```

标签表还多四列（不进文件名，只在 `tags.csv` 和预览页里筛）：
`风格`（赛璐璐/厚涂/水彩/3D/实拍/线稿）、`色调`（冷/暖/中性/黑白/高饱和/低饱和）、
`字幕`（有/无）、`运镜`（固定/推/拉/摇/移/跟/慢镜头/第一人称/手持/变速）。
前三个由模型判断；运镜只看静帧判不准，只在「导入已有片段」时按文件名填。

每段约 2.5 秒，400 段约 17 分钟。

**其它顺手功能**：路径支持拖入（文件夹 / XML 拖进窗口自动识别）、
勾选项和路径自动记忆（程序目录的 `设置.json`）、续跑跳过已完成、
跑完日志点名失败片段（详细原因在 `解析失败.txt`）。

### ③ 素材库模式：打好的片段直接进库

适合已经按作品分好文件夹的素材库，比如 `D:\素材库\某部作品\`。

1. 输出目录选到**作品文件夹本身**（不是它的上级，也不是 `_标签数据`）
2. 勾上「直接存入素材库文件夹（不建 clips 子目录）」，选到有视频的文件夹会自动勾
3. 开始打标

结果：

```
某部作品\
├── 你原有的片段                       ← 一个不动
├── 全景 夜晚 金发少女 撑伞 水面.mp4    ← 新片段直接落在这里
└── _标签数据\                        ← 程序的管理目录
    ├── tags.csv      标签表（多批自动合并）
    ├── preview.html  预览页
    ├── thumbs\  cache\
```

- 命名改成手写风格：`景别 光线 主体 动作 场景.mp4`，空格分隔、无编号；
- 撞名自动加 `-2`、`-3`，**绝不覆盖已有文件**；清理只删本程序生成、记录在清单里的文件；
- 不勾这个选项时，行为仍是原来的独立输出：`clips\` + 8 字段下划线命名 + 编号。

### ④ 导入已有片段：把老素材也变成可搜索的

以前手动命名、手动分好类的素材，不用重跑模型就能进标签表。

1. 切到「③ 素材库」页
2. 库文件夹选**素材库目录**（单部作品，或包含多部作品的总库目录）
3. 点「导入已有片段」

（这一页跟「素材目录 / 输出目录」是两个独立概念：这里只读已有文件，
不会往库里复制任何东西。）

**全库搜索**：把库文件夹选到总库目录（含多个作品子文件夹的那层），
点底部「生成全库预览」，会在总库根目录生成：

- `全库预览.html` —— 所有作品的片段混在一页，多一行「作品」筛选，搜索框也能搜作品名
- `全库标签.csv` —— 合并的总标签表，多一列「作品」

每部作品自己的 `_标签数据\preview.html` 仍然保留。合并的是各作品的
`tags.csv` 与缩略图引用，所以导入新作品或重新打标后要再点一次才会更新。

**改了文件名？** 再点一次「导入已有片段」：模型打标的行会按文件大小
自动认领到新名字（同尺寸唯一时），标签保留；手写命名的行按新名字重新解析，
旧记录自动清理。认领不了的行会提示「清理失效记录 N 条」，按新名字重新导入即可。

程序读文件名反推标签：`中景 夜晚 女主咬勋章.mp4` → 景别=中景、光线=夜晚、主体=女主咬勋章；
认不出的描述整段进「主体」，预览页照样能搜。`混合` 这类自定义类别会原样保留到景别列
（近景/中景/空镜/远景/特写等标准景别也认）。**不改名、不复制、不动原片**，
每次导入都会按当前文件名重新解析（改名或词表更新后重跑即可生效），不会重复加行。
选总库目录时逐个作品导入，每部各自生成 `_标签数据\`。

代价要说清楚：名字里没写的字段（情绪、动作细类）导进来是空的，
要补齐就用下面的 ⑤。

### ⑤ 只补标签：给已有素材补全字段，不改名、不复制

④ 只能从文件名里读信息。想让模型真正看一遍画面、把情绪/场景/动作这些
补上，又不想让它改名或复制文件，用这个：

1. 「① 打标」页，素材目录选**要补的那部作品文件夹**
2. 勾上「只补标签（不改名、不复制）」—— 输出目录那一格会被忽略
3. 点「开始打标」

跑完后：

- 视频**原地不动**：不改名、不复制、不移动、不删除；
- 标签写回 `<作品文件夹>\_标签数据\tags.csv`，预览页同步重建；
- 已有记录**沿用原编号**，新片段接在最大编号之后；
- 改过名或删掉的旧记录会被清掉，日志写「清理失效记录 N 条」；
- 每个片段约 2.5 秒，132 个大约 6 分钟。

和 ④ 的分工：

| | 速度 | 能填的字段 | 什么时候用 |
|---|---|---|---|
| ④ 导入已有片段 | 每个约 0.15 秒 | 只能从文件名读 | 全库先变成可搜索的 |
| ⑤ 只补标签 | 每个约 2.5 秒 | 模型看图，8 个字段基本都能填 | 精修近期要剪的那部 |

### ⑥ 发送到 Premiere：筛好的片段直接进 PR 项目

装好 PR 面板后（安装见下），不用再开文件夹拖素材：

- **③ 素材库页**「发送到 Premiere」：把库文件夹的视频整批发进 PR；
- **① 打标页**「发送到 Premiere」：把本批片段（clips\ 或库根）整批发；
- **预览页**：勾选任意几个片段 → 点「发送到 Premiere（已选 N）」→
  下载 `tm_cmd.json` → **把它拖进 TagMaster 窗口**，即完成发送。

片段会自动导入 PR 项目的 `TagMaster` bin，并按作品名建子文件夹；
导入的是完整文件（不切割），后续剪辑都在 PR 里自由安排。

**安装 PR 面板（一次性）：**

1. 开调试模式（未签名扩展必须），普通 cmd 执行：

   ```cmd
   reg add "HKCU\Software\Adobe\CSXS.9"  /v PlayerDebugMode /t REG_SZ /d 1 /f
   reg add "HKCU\Software\Adobe\CSXS.10" /v PlayerDebugMode /t REG_SZ /d 1 /f
   reg add "HKCU\Software\Adobe\CSXS.11" /v PlayerDebugMode /t REG_SZ /d 1 /f
   reg add "HKCU\Software\Adobe\CSXS.12" /v PlayerDebugMode /t REG_SZ /d 1 /f
   ```

2. 把仓库里的 `cep/tagmaster-panel/` 整个文件夹拷到：
   `%APPDATA%\Adobe\CEP\extensions\com.tagmaster.prpanel\`（extensions 不存在就新建）
3. **完全关闭** Premiere 再打开 → 菜单 `窗口 → 扩展程序 → TagMaster 素材桥`
4. 面板显示「监听中」即装好。之后 TagMaster 里点发送，面板 1 秒内接收导入。

说明：这套面板的命令桥参考了 TuanToolKit（原作者）的文件轮询方案，命令文件
用 `tm_cmd.json` + `tm_cmd` 键，与 TuanToolKit 的 `pr_cmd.json` 互不冲突，可同时安装。
面板只能在你装有 Premiere 的机器上工作；TagMaster 发送端只写一个 JSON 文件，
PR 不在线时命令会保留，下次 PR 开起来且面板运行时才被消费。

## 七、常见问题

**Q：双击 bat 闪一下就没了？**
看目录下有没有 `启动错误.log`，内容就是原因。最常见的是 `python\` 不完整。

**Q：提示显存不足？**
关掉其它吃显存的程序。MiniCPM 占 3 G，DinoV2 占 1.5 G，8 G 卡刚好够。
显存小于 8 G 的卡跑不动。

**Q：切片段提示「全部源文件都找不到」？**
原片挪了位置。在「源视频目录」里选原片现在所在的文件夹；
如果文件名也改了，用「路径替换」填旧目录 → 新目录。

**Q：景别那一列全是空的？**
缺 `preprocessor_config.json`。点右上角「环境检查」→ 一键生成。

**Q：情绪判断感觉不准？**
它的准确率确实是八个字段里最低的，大部分会落在「平静 / 孤独」。
当参考用，不要拿它做唯一筛选依据。

**Q：能不能不用显卡？**
不能。模型必须加载到 CUDA 上，CPU 跑一段要几十秒。

**Q：打标会不会覆盖我素材库里已有的文件？**
不会。复制前查同名，撞名自动加 `-2`、`-3`；清理只删本程序生成、
且记录在清单里的文件，你手动放进去的视频永远不会被碰。

**Q：输出目录能放在程序目录外面吗？**
能，任何盘符都行。素材库模式下还能直接输出到作品文件夹里。

准确说：**程序里没有写死任何路径**，没有固定盘符，也不要求放在某个文件夹。
素材目录、输出目录都按你在界面上选的走，中文、空格、深层目录都支持；
输出目录留空时才自动推导成「素材目录名_打标」。
程序目录里的 `设置.json` 只是记住上次选的路径（图方便），换电脑、换位置、
删掉它都不影响数据 —— 重新选一下就好。整个程序文件夹拷到别的机器也能直接跑。

**Q：拖进去没反应？**
看日志里有没有「拖放已就绪：已启用」。没有就是被系统拦了，
改用「浏览」按钮，或把文件夹直接拖到 `TagMaster.bat` 图标上启动。

**Q：怎么知道哪些片段失败了？**
跑完最后一行日志会写「本次失败 N 个：xxx.mp4」；详细原因和模型
原始输出在输出目录的 `解析失败.txt` 里。勾「续跑」再点一次只会重试这几个。

**Q：老素材（手写命名的）能一起搜吗？**
能，用底部「导入已有片段」。它只读文件名，不改名、不复制；
名字里没写的字段（情绪等）会是空的，想补要用模型重跑。

**Q：运镜那一列为什么总是空的？**
模型只看两张静帧，判断推拉摇移基本靠猜，会给你错误的筛选结果，所以不让它填。
只有「导入已有片段」会按文件名里的「慢镜头 / 第一人称 / 固定」这类词填上。

## 八、制作思路

这一节讲**为什么这么设计**，以及每一步踩过什么坑、被什么数据推翻过。
起点来自 **TuanToolKit**（原作者）的思路，后面的取舍是在它的基础上改出来的。

### 8.1 起点：原作者做了什么

原工具的自动提纯是一条这样的流水线：

```
视频 → FG-CLIP 逐帧编码成向量 → 相邻帧相似度突变处切场景 → 存 Lance 索引
     → 12500 条预设 prompt 编码成向量 → 和每个场景比对，每类取 Top-1
     → 四类（主体/动作/场景/情绪）全中才保留 → MiniCPM-V 逐段验真 → 导出
```

**这个设计本身是成立的**：用检索解决"画面和文字怎么对应"，用 VLM 解决"检索结果可不可信"。
它的两个思路被直接继承下来了——**画面必须有模型参与**，以及**结果必须二次校验**。

问题出在三个地方，都是实测出来的：

| 现象 | 原因 |
|---|---|
| 418 段只输出 22~82 段 | 四类全中是硬门槛，凑不齐就整段丢 |
| 标签常错（`门_祈祷` 配湖面） | 每类必须给一个 Top-1，画面里没有也得挑最像的 |
| 搜"背影 雨中" 0/3 命中 | CLIP 对镜头语言类词汇不敏感，跨模态本来就弱 |

### 8.2 关键转向：从"用检索做打标"改成"让模型看图回答"

原工具的 12500 条 prompt，本质是**在没有 VLM 的年代，用检索引擎假装打标**：
"这个场景最像哪条句子 → 那条句子里嵌的词就是标签"。

既然手上已经有 VLM，就不需要这层壳了。直接问：

```
不问：这个画面和"一张以男人为主体的动画风格插画"有多像？（算分）
而问：画面里有几个人？他在做什么？这是什么场景？（回答）
```

**一个算相似度，一个给答案。** 前者只能排序，后者才能产出结构化字段。

### 8.3 八个字段是怎么定的

不是凭空想的，是从作者自己 3749 个素材文件名里统计出来的：

```
中景 1126  近景 831  空镜 369  远景 278  特写 72     ← 景别占六成
夜晚 192   室内 58   夕阳 43   黄昏 33              ← 时间光线
正面 69    背影 50   双人 43   回头 36   侧脸 22     ← 朝向与人数
对话 183   动作 148  战斗 87                         ← 动作
微笑 24    哭泣 20   表情 35                         ← 情绪
```

最终取 8 个：`景别 / 人数 / 朝向 / 主体 / 动作 / 场景 / 光线 / 情绪`。
**这 8 个能覆盖上面所有高频词**，且每个都有确定的取值集合（除了主体/动作/场景是自由词）。

### 8.4 为什么枚举字段要给候选值、允许说"无"

第一版是自由描述，输出的是"一位少女静静地伫立在黄昏的走廊里"——没法当标签用。

改法：枚举字段（景别/人数/朝向/光线/情绪）**给定候选值**，自由字段（主体/动作/场景）**限 1-3 个词**。

更关键的是**明确允许填"无"**。原工具的毛病就是不许说不知道，于是画面里没有门也得挑一个。
加了这条之后，418 段里有 135 段"动作"是空的——**这是正常的，不是失败**。

### 8.5 为什么每段抽 2 帧

模型只看静态图。抽 1 帧判不出动作（只能看到一瞬间的姿势），抽 3 帧以上收益递减
（3 秒的片段，三帧几乎是同一瞬间），而每多一帧视觉 token 就多一份。

**2 帧是"能判动作"和"不拖时间"的折中点**，位置取时长的 1/3 和 2/3——
不抽首尾，因为片段首尾常有转场、闪白、黑场。

### 8.6 为什么景别要单独一个模型

这条是**返工出来的**。第一轮 VLM 跑完，7 个景别档位只用了 5 个：

```
中景 162、空镜 87、大特写 66、特写 51、全景 46   ← 近景 0、远景 0
```

一个 7 分类任务只输出 5 个类别，说明有系统性偏差。于是拿专门训练的景别分类器
（aslakey/shot-scale，DinoV2 微调）对同样两帧重判，两套结果**只有 53% 一致**。
抽 8 个分歧样本肉眼判：**DinoV2 对 5 个，VLM 对 1 个**（另 2 个都不对）。

所以最终定成：**景别用 DinoV2，其余 7 个字段用 VLM**。
`人数=无人` 时强制景别为"空镜"（DinoV2 没有这个类别）。

> 通用经验：**别相信单模型的自我一致**。判断方法是看档位有没有被用全——
> 该用的类别没用上，就是模型在这个维度上有偏，不是数据恰好如此。

### 8.7 为什么输出文件名而不是数据库

三个理由，都很实际：

1. **文件名即索引**：资源管理器按名称排序，因为景别是第一个字段，同景别的片段自动聚在一起
2. **谁都能读**：Excel、PR、任何工具都能用，不依赖某个程序还活着
3. **可逆**：标签错了重跑一遍就行，原片一个字节没动（复制改名，不是移动）

### 8.8 为什么切片段不重新渲染

PR 导出的 XML 里每个片段都有**源文件的帧号**（`<in>` / `<out>`），
所以可以拿 ffmpeg 直接按帧号切原片，走 NVENC 硬件编码：

```
418 段，254 秒，总时长 1425 秒 = 原片 23.7 分钟，一帧不多一帧不少
```

比在 PR 里重新导出快几十倍，而且没有二次压缩的画质损失。
坑在于 XML 里 `<in>/<out>` 是源帧、`<start>/<end>` 是时间线帧——**用错了会全部错位**。

### 8.9 已知取舍

| 短板 | 表现 | 为什么没修 |
|---|---|---|
| 情绪区分度弱 | 75% 落在"平静/孤独" | 情绪本身主观；靠 VLM 判已经到极限，要更细得换更大模型 |
| 朝向在暗光下不可靠 | 兜帽、远景背影判成正面，约 5~10% | 单帧信息不足，除非喂视频 |
| 没有"近景"档 | DinoV2 只有五类（大特写/特写/中景/全景/远景）+ 空镜，胸以上会归到特写或中景 | 分类模型换不了，除非自己训 |
| 没有运镜判断 | 推拉摇移判不出来 | 需要多帧光流，实测跑不完（每段要扫全片） |
| 文件名导入信息有限 | 情绪、人数、朝向常为空，只能靠搜描述 | 不跑模型只能读到名字里写的东西 |
| 两种模式命名不同 | 素材库模式是空格无编号，普通模式是下划线+编号 | 前者为了和手写库统一，后者为了可排序、可检索 |
